Linguagem visual compartilhada para todo instalador de solução. Ponha duas tags na sua página, use as classes .i-* e o instalador já sai padronizado — light e dark inclusos.

Como usar

Duas tags no <head>, uma no fim do <body>. Nenhum build, nenhuma dependência. A versão fica travada na URL: o que você publicou hoje continua idêntico daqui a um ano.

Tokens

Subconjunto do DS StartSe que um instalador pode usar. Nada fora desta paleta. Todo valor é uma custom property — var(--i-action), nunca #0066BE —, e é por isso que o tema inteiro troca com um atributo.

Light
Dark — só o que muda

O dark é um patch: redefine superfícies, tinta e ação, e mantém o matiz das cores semânticas trocando apenas o fundo por um tint escuro. Três regras: a ação vira o pure #0080ED e clareia no hover em vez de escurecer; sombra continua zero; profundidade é borda, nunca elevação.

Estrutura da tela

Todo instalador é um takeover com três regiões fixas. O conteúdo do passo é a única parte que varia entre instaladores.

.i-topbar + .i-shell

Barra sticky de 60px, grid de 290px (stepper) e conteúdo fluido. Abaixo de 900px o grid vira coluna única e o stepper para de ser sticky.

.i-topbar · .i-topbar__in
.i-shell · .i-stepper · .i-flow
Um passo por vez. Passo futuro não aparece no conteúdo; passo concluído colapsa em .i-summary com os números que provam o resultado. Todo passo termina em verificação. O último passo confere a instalação de verdade — webhook, login — antes de liberar o CTA final. Privacidade sempre visível. A nota "o que fazemos com os seus dados" mora no stepper (.i-privacy), não no rodapé.

Componentes

Especificação à esquerda, exemplo vivo à direita, HTML exato embaixo — o snippet é gerado a partir do mesmo markup que está rodando ali, então nunca sai de sincronia.

Botões

Três hierarquias, 44px, raio 2px. No máximo um primário por card. Desabilitado é cor flat, nunca opacidade. Carregando troca o rótulo pelo spinner sem mudar o fundo nem a largura. Destrutivo só dentro de modal de confirmação.

.i-btn--primary · --secondary
--tertiary · --danger · --sm
:disabled · .is-loading

Campos

Underline do DS: rótulo em cima, linha 1px embaixo, ajuda abaixo. Nunca caixa com borda. Foco engrossa para 2px na cor de ação. Erro troca linha e ajuda, e o texto diz o que falhou e como corrigir. Segredo é sempre type="password".

.i-field · .i-field__label
.i-field__input · .i-field__help
.i-field--error · .i-field__wrap

Escolha única

Radio para 2–3 opções curtas; card de opção quando a escolha precisa de descrição e consequência. Nunca dropdown para menos de 4 opções. A opção recomendada vem primeiro e diz que é a recomendada.

.i-radio · .i-check
.i-option · .i-option--selected

Stepper

Quadrado de 30px, raio zero. Concluído teal com check; ativo azul com número; futuro branco com contorno — cor flat, nunca opacidade. O JS move o estado; o HTML já nasce com o passo 1 ativo, então funciona sem JS.

.i-stepper · .i-step
.i-step--done · --active · --future
StartSeUI.stepper(el).active(n)

Card de passo

O contêiner de tudo que o passo pede: eyebrow azul com a posição, título em verbo, um parágrafo de contexto, campos, ações. Só existe um por tela.

.i-card · .i-card__actions
.i-eyebrow · .i-h-step · .i-body

Execução e log

Enquanto roda: spinner + frase com expectativa de tempo. Cada etapa concluída entra no log — check teal, nome à esquerda, detalhe técnico em mono à direita. Erro interrompe, nomeia a causa provável e oferece a próxima ação. Nunca "erro desconhecido".

.i-run · .i-log__row
.i-log__det · .i-log__err

Superfícies de status

Resumo de passo concluído com badge teal e os números que provam o resultado. Alertas com border-top na cor semântica. Aviso é condição degradada que não bloqueia. Conclusão só depois da verificação de verdade.

.i-summary · .i-badge-check
.i-alert--info · --warn · --error
.i-done · .i-access

Tags, chips e tabs

Tag grita status: caps 10px, fundo semântico, raio zero. Chip só descreve: sentence case, raio 2px. Tabs para vistas paralelas do mesmo conteúdo — nunca para os passos, que são o stepper. As setas do teclado navegam.

.i-tag--info · --ok · --warn · --err
.i-chip · .i-tabs · .i-tab--active
data-i-tabs · data-i-tab

Copiável, progresso e tabela

Campo copiável para valor que vai para outra ferramenta — o botão vira "Copiado" por 2s. Progresso só quando o total é conhecido; sem total, spinner, nunca porcentagem inventada. Tabela para o inventário do que foi criado: sem zebra, sem borda externa.

.i-copy + data-i-copy

Modal de confirmação

Comportamentos por atributo

Marcação declarativa: você escreve HTML, o kit liga o comportamento. Os cliques são tratados por delegação no document, então HTML injetado depois — um passo que aparece, um log que cresce — já funciona sem chamar nada.

AtributoO que faz
data-i-copyBotão que copia. Sem valor, copia o <code> do .i-copy em volta (ou o [data-i-copy-source]); com valor, copia o valor. Vira "Copiado" por 2s. Tem fallback para contexto sem permissão de clipboard.
data-i-copy-sourceMarca de onde vem o texto, quando o .i-copy tem mais de um candidato.
data-i-tabsNo container .i-tabs. Aplica os papéis ARIA e liga ←/→/Home/End.
data-i-tab="#painel"Em cada botão de tab, apontando para o .i-tabpanel que ele controla.
data-i-theme-toggleAlterna light/dark e persiste em localStorage. Mantém o aria-pressed em sincronia.
data-i-modal-open="#id"Abre o .i-modal-scrim daquele id, com trap de foco e trava de scroll.
data-i-modal-closeFecha o modal aberto e devolve o foco para quem o abriu.
data-i-modal-dismissibleNo scrim: libera o fechamento por clique fora. Sem ele, só Esc ou botão — sair sem querer de uma confirmação destrutiva é pior que um clique a mais.
data-i-revealBotão que mostra/esconde o valor de um campo type="password", trocando o ícone.
data-i-stepMarca cada passo do stepper para a API stepper() encontrar.
data-i-progress-labelRótulo inicial da barra de progresso.

API JS

O global StartSeUI cobre o miolo de um instalador: mover o stepper, escrever o log, travar o botão enquanto roda, confirmar o irreversível. Todo texto que você passa entra por textContent — mensagem de erro de API é dado não confiável e o kit trata como tal.

Um passo, ponta a ponta

O padrão que se repete em todo instalador: trava o botão, abre o log, executa, e ou conclui o passo ou para com a próxima ação na mão do aluno.

stepper · runLog · button
progress · modal.confirm · theme 
const passos = StartSeUI.stepper('[data-i-stepper]')
const log    = StartSeUI.runLog('#execucao')
const botao  = StartSeUI.button('#instalar')

async function instalar() {
  botao.loading(true)
  log.clear().start('Publicando os workflows — leva alguns segundos.')

  try {
    const n8n = await conectar()
    log.ok('Conectando ao seu n8n', `versão ${n8n.version} · API ok`)

    const { criados, total } = await publicar()
    log.ok(`Publicando ${total} workflows`, `${criados} criados · ${criados} ativos`)

    log.stop()
    passos.active(2)                      // passo 1 vira concluído
  } catch (erro) {
    log.fail('Publicando os workflows', {
      error: erro.mensagemParaOAluno,     // causa provável + como corrigir
      retry: instalar,                    // o botão só aparece se houver retry
    })
  } finally {
    botao.loading(false)
  }
}

// Ação que sobrescreve algo do aluno: confirma nomeando a consequência.
if (conflitos.length) {

    text: 'Sobrescrever apaga as alterações que você fez neles.',

}

Voz e regras de escrita

O kit padroniza a aparência; isto padroniza o texto. Vale tanto quanto o CSS — um instalador bonito que fala mal continua assustando o aluno.

Assim
  • "Instalar os workflows" — título é verbo, você direto, sentence case.
  • "Leva alguns segundos" — toda espera diz quanto tempo.
  • "10 criados · 10 ativos" — resultado se prova com número.
  • "Gere outra em Settings → n8n API" — erro sempre diz o caminho da correção.
  • "Apague a chave depois da instalação" — segurança como instrução, não como aviso jurídico.
Nunca
  • Emoji, exclamação dupla, "Parabéns!!" — celebração é o resultado, não confete.
  • Jargão sem tradução: "RLS", "idempotente" — diga o efeito ("regras de segurança").
  • ALL CAPS fora da tag INSTALADOR e dos eyebrows.
  • "Erro desconhecido" — todo erro nomeia a causa provável e a próxima ação.
  • Prometer o que não verificou: "Pode usar" só depois do passo de conferência.
